Second-Order Observability

Chaz Dinkle · Myrgic Labs

Working note · paper in progress

A monitoring system watches your services. What watches the monitoring system? The usual answer is another monitoring system, and the usual place that argument stops is one level up, on the grounds that the observer is more reliable than the thing it observes.

That assumption is load-bearing, and AI agents break it.

The claim

Declared observability is optional when the observer is more reliable than the referent, and mandatory when it is not. Synthetic observers — agents that observe and act in the same loop — cross that line by construction.

Infrastructure already built most of this and did not particularly notice. A Prometheus ServiceMonitor is a declared observation: a record stating that something should be watched. Kubernetes has Ready=Unknown. Nagios has UNKNOWN, held carefully distinct from CRITICAL — a plugin that could not produce a result is not the same as a plugin that produced a bad one.

So the mechanism is not new, and this note does not claim it is. What is missing is the reflexive case: none of these patterns can express an observer observing something that observes back.

Where the existing pattern runs out

Three gaps, each verified against primary sources rather than recollection.

1. The observer is not in the declaration

Nothing in the ServiceMonitor schema names the Prometheus that will scrape it. The relationship is a two-way label join — the Prometheus resource carries a serviceMonitorSelector, the ServiceMonitor carries labels — computed at reconcile time across two objects that never reference each other.

"Who observes this?" is therefore not a lookup. It is a join across the cluster, recomputed per query. And "is anything observing this at all?" has no cheap answer at all.

2. Nothing is silence, not zero

A selector that matches nothing produces no series. Not 0 — nothing. The up metric is 0 only for a target that was scraped and failed; a target that was never discovered has no row to be zero. PromQL ships absent() specifically to manufacture a value out of that void, which is a clear signal the void is a problem.

A monitor that was never wired up and a monitor reporting perfect health produce identical output: no alerts.

3. Self-observation cannot close

kube-prometheus ships a ServiceMonitor pointing Prometheus at itself. It catches degradation. It cannot catch total failure — if the process is gone, nothing remains to record that it is gone. The failure mode is silence, and silence is what success looks like.

This is Thompson's trusting-trust problem in a monitoring stack: a self-hosting system cannot certify itself by self-examination. Wheeler's answer to Thompson was an independent, externally-rooted compilation path. The answer here has the same shape.

Why agents change the math

Every one of those gaps was survivable because of one assumption: the observer is more reliable than the referent. Prometheus fails far less often than what it watches, so one unwatched level at the top is an acceptable rounding error.

An LLM agent is not that. It is unreliable, observing, and acting in the same loop — and its self-report is narrative rather than trace. An agent that reports having done something it did not do is producing a correct-looking output with no consumer that could catch it. That is not a rounding error at the top of the stack; it is the same defect the stack exists to detect, relocated into the detector.

There is prior art for exactly this, from control theory. Feldbaum's dual control (1960–61) showed that when a controller's actions both steer a process and generate the information used to estimate it, estimation and control can no longer be designed independently — the acting corrupts the observing. The classical separation principle holds only while the observer does not disturb what it observes. An agent in a loop violates that premise by definition.

The minimal pattern that closes

Make the observation itself a first-class record:

{ "id": "obs-A-of-B", "referent": "B", "observer": "A", "pointer": "..." }

observer is required at load time — a declared observable with no observer is not a malformed record, it is not a record

Then the reflexive part: the minimum cycle length that can report its own failure is two. Two processes that each observe the other survive the death of either one. A process that observes itself cannot.

There is a running demonstrator — Python standard library only, falsifiable with kill -9. Here is real output from it. Two processes, A and B, observe each other; C observes only itself.

Kill B, and its partner reports it within the grace window:

ID           REFERENT OBSERVER  STATUS        LAST_ATTEMPTED  NOTE
obs-A-of-B   B        A         unobserved    0.5s ago   heartbeat 4.25s old (stale)

the 2-cycle: A is alive, still checking, and says so

Now kill C, the self-observer, and wait twelve seconds:

ID           REFERENT OBSERVER  STATUS        LAST_ATTEMPTED  NOTE
obs-C-of-C   C        C         healthy       12.6s ago  self_report='ok', age 1.07s

C has been dead for twelve seconds. Its own row still reads healthy.

C is not reported as failed, or unknown, or stale. It is reported as healthy, because the only process declared to check that row was the process that died. The record is frozen mid-sentence and nothing in the system is structurally capable of noticing.

A separate manual sweep does catch it — and it has to be manual, because it stands in for what first-order observability actually falls back on: a human eventually looking.

obs-C-of-C   status=healthy   last_attempted 12.7s ago  STALE (unreconciled for 12.7s)

the audit sweep, run by hand, is the only consumer that notices

The difference between those two outcomes is cycle length 2 versus cycle length 1. Not better code, not a longer timeout — a structural property of the observation graph.

What this does not claim

  • Not novelty of declared observers or of unobserved as a state. An adversarial prior-art review returned anticipated on the mechanism, and that verdict stands. The contribution is the bridge and the reflexive gap, not the primitive.
  • Not a rate. Silent-failure instances are reported as a count. The denominator — how often this happens across systems generally — is not something this work measured, and naming that gap is part of the point.
  • Not control. A synthetic observer is an observer-actuator, and observability and controllability are duals. This note treats only the observation half. The demonstrator shows that an observation can be trusted; it shows nothing about whether an action was correctly effected.
  • Not a product. The demonstrator is a reference implementation with no network, no auth, and no persistence.

Status
